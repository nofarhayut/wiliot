# Task 1 — Infrastructure (Terraform)

> 📊 **[View the visual overview →](https://claude.ai/code/artifact/29d1c357-e968-43d0-9e68-298841ba8b43)** — a one-page presentation of the whole assignment.

The AWS foundation, provisioned entirely with Terraform. Each resource is its own
reusable module, composed together in one [`environments/dev`](environments/dev) root
with remote state in S3. Nothing is clicked in the console.

Deployed to AWS account `092988563851`, region `us-east-1`.

## Resources

| Resource | Module | What it is |
|---|---|---|
| **VPC** | [`modules/network`](modules/network) | VPC (`10.0.0.0/16`), 2 public + 2 private subnets across 2 AZs, internet gateway, one NAT gateway, route tables |
| **EKS** | [`modules/eks`](modules/eks) | Cluster `wiliot-dev` (K8s 1.31) + a managed node group of 2× `t3.medium` |
| **RDS** | [`modules/rds`](modules/rds) | Private PostgreSQL, subnet group, security group (5432 from the EKS SG only), generated password |
| **ECR** | [`modules/ecr`](modules/ecr) | Container image repositories + a lifecycle policy |
| **IAM** | [`modules/iam`](modules/iam) | The roles EKS needs — control plane + worker nodes |

## Considerations (the "why")

- **One module per resource** — reusable and easy to read. Dependency order is
  network / iam / ecr, then eks, then rds.
- **Each security group lives with the thing it protects** — the RDS security group is in
  `modules/rds` and only allows port 5432 from the EKS cluster's security group. So the
  database is reachable only from inside the cluster, nothing else (SG-to-SG, no CIDRs).
- **The database is private** — no public access, encrypted at rest.
- **No passwords in the code** — the DB password is generated by Terraform and kept only as
  a `sensitive` output in the encrypted S3 state. Read with `terraform output -raw rds_password`.
  Secrets Manager would be the production choice; skipped because the assignment IAM user
  can't create secrets there.
- **Remote, locked state** — S3 backend with native locking (`use_lockfile`, no DynamoDB).
- **One tag on everything** — `team = devops`, set once on the provider, for cost tracking.
- **Cheap by default, ready to scale** — one NAT, a small DB, two small nodes (demo
  trade-offs). The network is split from the cluster, so a second cluster can share the VPC later.

## Deploy / inspect

```bash
export AWS_PROFILE=nofar-yaba AWS_REGION=us-east-1
cd environments/dev
terraform init
terraform plan
terraform apply

terraform output                    # cluster endpoint, ECR URLs, rds_endpoint, ...
terraform output -raw rds_password  # sensitive; never printed otherwise
```

The state bucket is created once, before the first `init`, with
[`scripts/bootstrap-backend.sh`](scripts/bootstrap-backend.sh).
